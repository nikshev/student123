# Contract: події перегляду (tracking events)

**Feature**: 001-bunny-video | **Канал**: `runtime.publish(...)` → tracking-логи Open edX
**Первинний запис метрики** «додивились до кінця» (конституція V, SC-004/005).

## 1. Імена подій

| Ім'я | Коли |
|---|---|
| `xblock-video.player.play` | Початок або продовження відтворення (FR-001-12) |
| `xblock-video.player.pause` | Пауза |
| `xblock-video.player.complete` | Повний перегляд: `current_time / duration ≥ completion_threshold` (FR-001-14) |

Імена не залежать від джерела відео (Bunny/YouTube/Vimeo) — R7.

## 2. Схема payload (публікується хендлером `save_event`)

```json
{
  "user_id": 12345,
  "course_id": "course-v1:demo+math101+2026",
  "unit_usage_key": "block-v1:demo+math101+2026+type@vertical+block@unit1",
  "video_ref": {
    "source_type": "bunny",
    "video_id": "32d140e2-e4f4-4eec-9d53-20371e9be607"
  },
  "event_type": "complete",
  "current_time": 590.0,
  "duration": 612.5,
  "config_version": "1.0.0"
}
```

| Поле | Правила |
|---|---|
| `user_id` | `request.user.id`; анонімні події не публікуються (плеєр доступний лише зарахованим) |
| `unit_usage_key` | `self.scope_ids.usage_id` блоку (юніт = його parent, адресується блоком) |
| `video_ref.source_type` | `bunny` \| `youtube` \| `vimeo` |
| `video_ref.video_id` | GUID Bunny або нормалізований id/URL зовнішнього джерела |
| `event_type` | `play` \| `pause` \| `complete` |
| `current_time`, `duration` | float-секунди; для Bunny `duration` сервер бере з метаданих (недовіра клієнту) |
| `config_version` | з `bunny_config.yaml` (принцип III: прогони з різними порогами розрізняються без читання коду) |

`timestamp` додається tracking-системою; додаткові поля Open edX
(host, referer, agent) — автоматично, їх не контролюємо.

## 3. Семантика

- **Сесія** = одне завантаження студентського в'ю. `complete` — ≤ 1 на сесію
  (клієнтський прапорець); повторний старт після `ended` у тому ж в'ю —
  нова сесія. Два повні перегляди того ж відео = два `complete` (US3.4).
- **Пауза без `complete`** = «неповний перегляд» у звіті (US3.2); закриття
  вкладки фіксується наявною `pause`/відсутністю `complete` — прийнятно.
- **Перемотка** (edge case spec): `complete` вимагає порогу, а не факту
  досягнення кінця; повторна перемотка через поріг у межах сесії не
  дублює подію (прапорець).
- **`play` після `pause`** = новий `play` (пари play↔pause дають сумарний
  час перегляду майбутній аналітиці).
- **Помилка відтворення** (FR-001-10): подія не емітується; UI показує
  повідомлення. Метрика «відтворили з першої спроби» (SC-002) на етапі 2
  виводиться з наявності `play` без попереднього `error` у логах плеєра —
  поза скоупом цієї фічі, але події не заважають.

## 4. Доступність даних (FR-001-15, SC-004)

Події опиняються в tracking-логах синхронно з публікацією; частка повних
переглядів по юніту обчислюється з них наступного дня споживачем звітів
(етап 2). Ця фіча гарантує лише первинний запис — контракт споживання
звітів у цьому репозиторії не фіксується.

## 5. Тестованість

Хендлер тестується з мокованим `runtime.publish` (перевірка payload —
фікстури без мережі); чиста порогова логіка — jest. Приклади фікстур:
повний перегляд (0.97), неповний (0.40), перемотка (0.99 після стрибка),
повторний перегляд (два `complete`).
