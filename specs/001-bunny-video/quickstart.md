# Quickstart: валідація фічі end-to-end (001-bunny-video)

**Призначення**: сценарії ручної перевірки після розгортання — доводять, що
фіча працює наскрізно, без читання коду імплементації. Кожен сценарій
посилається на FR/SC з [spec.md](./spec.md) і на контракти.

## S0. Передумови (один раз)

1. Tutor розгорнуто на VPS; XBlock `video_xblock` встановлено в образ
   (tutor-plugin), LMS/CMS перезапущено (цикл збірки 10–20 хв).
2. Bunny Stream: створено бібліотеку; у налаштуваннях **Security**
   увімкнено Token Authentication (збережено token security key), в
   Allowed domains додано домен LMS (без схеми, напр. `lms.example.org`),
   увімкнено Block Direct URL File Access.
3. Через tutor secrets виставлено `BUNNY_STREAM_LIBRARY_ID`,
   `BUNNY_STREAM_API_KEY`, `BUNNY_STREAM_TOKEN_KEY`.
4. CSP LMS: `frame-src https://player.mediadelivery.net` присутній.
5. Створено тестовий курс з юнітом; тестовий учень зарахований; включено
   «Відео» в advanced module list (як для форка).
6. Саніті: `python3 scripts/trace.py --check` — зелений.

## S1. Завантаження MP4 одним кроком (US1.1, FR-001-01/05, SC-001)

1. Studio → юніт → блок «Відео» → вкладка Bunny → «Завантажити» → файл
   `sample.mp4` (≤ 100 МБ).
2. Очікується: прогрес-бар до 100 %, далі стан «Обробляється…», протягом
   ~1 хв — «Готово» з тривалістю (сек), що збігається з тривалістю файла.
3. Без жодних ID/сторонніх сервісів. Публікуємо юніт.
4. Регресія: `video_info` у Network-логі Studio повертає `status: 4`.

## S2. Обрив мережі → resume (US1.2, FR-001-03)

1. Почати завантаження файла ~200 МБ; у DevTools → Network → Offline на
   ~50 %; повернути Online.
2. Очікується: завантаження продовжується з місця обриву (не з 0 %).
3. Жорсткіший кейс: перезавантажити сторінку Studio на 60 % і вибрати
   той самий файл — resume з 60 % (tus-js-client у localStorage).

## S3. Непідтримуваний файл (FR-001-02)

1. Вибрати `notes.pdf` / `video.avi`.
2. Очікується: зрозуміле повідомлення «Формат не підтримується: MP4, MOV,
   WebM» до початку передавання; можна одразу обрати інший файл.

## S4. Файл понад ліміт (FR-001-04)

1. Вибрати файл > 2 ГБ (або тимчасово підняти/опустити `max_upload_bytes`
   у YAML і перевірити обидва напрями).
2. Очікується: відхилення з поясненням ліміту до передавання; блок лишається
   у стані «порожньо».

## S5. Публікація → учень дивиться (US1.4/US2.1, FR-001-07, SC-002)

1. Опублікувати юніт з READY-відео; зайти учнем (інкогніто).
2. Очікується: відео відтворюється в юніті, без переходів на сторонні
   сайти; у DevTools — iframe `player.mediadelivery.net/embed/…` з
   параметрами `token` і `expires`.

## S6. Токен спливає (US2.2, FR-001-09, SC-003)

1. Скопіювати URL iframe з S5.
2. Через 24 год (або підставивши в URL `expires` = вчорашній UNIX) відкрити
   URL у чистому вікні: очікується 403/відмова доступу.
3. Самоперевірка формули: локально обчислити
   `sha256_hex(token_key + videoId + expires)` і звірити з виданим token.
4. Відтворення, розпочате до спливу, не переривається (edge case spec).

## S7. Не зарахований учень (FR-001-08)

1. Інкогніто без зарахування: відкрити юніт.
2. Очікується: платформа не віддає юніт/відео (стандартна авторизація LMS);
   підписаного URL не існує поза рендером.

## S8. Видалене відео → повідомлення (US2.4, FR-001-10)

1. Видалити відео в дашборді Bunny (або `delete_video` зі Studio на іншому
   блоці, а юніт залишити опублікованим).
2. Очікується в учня: зрозуміле «Відео недоступне», не порожній плеєр.

## S9. Події в tracking-логах (US3, FR-001-12/13/14)

1. Учень: play → пауза на 30 % → play → додивитися до кінця.
2. Очікується в tracking-лозі LMS: `xblock-video.player.play` (двічі),
   `pause` (раз), `complete` (раз) — з `user_id`, `unit_usage_key`,
   `video_ref.video_id`, `current_time/duration`, `config_version`.

## S10. Поріг 95 % і повторний перегляд (FR-001-14, US3.4)

1. Перегляд №1: зупинитися на 94 % — `complete` відсутній (неповний
   перегляд у звіті видно за наявністю `play` без `complete`).
2. Перегляд №2: додивитися до кінця — один `complete`.
3. Перегляд №3 (та сама сторінка, replay): ще один `complete` — обидва
   перегляди збережені окремо.
4. Edge: перемотати на 99 % без фактичного перегляду — `complete` не
   зараховується, якщо накопичений час < 95 %.

## S11. YouTube / Vimeo (US4, FR-001-11)

1. Вставити посилання YouTube/Vimeo у блок, опублікувати.
2. Очікується: відтворення в плеєрі курсу без токен-параметрів; події
   `play/pause/complete` також пишуться (R7); недоступне посилання →
   повідомлення.

## S12. Мобільний WebView (edge case, етап 2 готовність)

1. Відкрити юніт у мобільному браузері / WebView-переглядачі.
2. Очікується: відтворення, пауза, complete — як у десктопі (iframe +
   postMessage). Регресія S9 на мобільному.

## S13. Гейт захисту відео (конституція, перед платними курсами)

1. `curl` на embed-URL з S5 **без** `token`/`expires` → 403.
2. `curl` з протухлим `expires` → 403.
3. `curl` з `Referer: https://evil.example.org` → блок (domain lock).
4. Прямий доступ до файла/play-URL без підпису → блок (Block Direct URL
   File Access).
5. Висновок фіксує людина: платний курс не відкривається учням, поки S13
   не пройдено повністю.

## S14. Видалення/заміна відео (FR-001-16)

1. Видалити відео з блоку: блок повертається до стану «порожньо», в Bunny
   об'єкт видалено (дашборд).
2. Замінити відео на інше: учень бачить нове; старі події інших юнітів у
   логах не змінюються (перевірити S9-логи сусіднього юніту).

## S15. Метрика наступного дня (FR-001-15, SC-004)

1. Після S9–S10 дочекатися наступного дня (або скористатись запитом до
   сховища tracking-подій).
2. Очікується: частка повних переглядів по юніту обчислюється з
   `complete`/`play` без додаткової обробки — первинний запис на місці.
